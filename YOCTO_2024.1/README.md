# Yocto Build (AMD rel-v2024.1, ME-XU1-6EG + ME-ST1)

The same Linux image as [../PETALINUX_2024.1](../PETALINUX_2024.1/), built with plain Yocto instead
of the PetaLinux tool. Base: AMD Yocto release **rel-v2024.1** = Yocto 4.1.4 **langdale**, the same
layer versions PetaLinux 2024.1 uses internally, so the XSA, the DPU IP and Vitis AI 3.5 are reused
unchanged.

> **Before the first build**
> - Build the hardware first ([../VIVADO_2024.1](../VIVADO_2024.1/README.md)): the XSA
>   `../VIVADO_2024.1/export/p01_xu1_st1.xsa` (`HDF_PATH` of the machine) is written by that build and
>   is not part of the repository.
> - `XILINX_SDK_TOOLCHAIN` in `build/conf/local.conf` (step 3) is the path of the Vitis 2024.1
>   installation on the build host (the folder that contains `bin/xsct`). Change it to your
>   installation; the value below is an example.
> - The build reuses the PetaLinux project's downloads (`DL_DIR`) and build results (first
>   `SSTATE_MIRRORS` entry) in `../PETALINUX_2024.1/p01-xu1-st1/build/`. Building PetaLinux first
>   makes the Yocto build much shorter; without it, Yocto creates that download folder and builds the
>   missing parts itself.
> - Every Yocto terminal starts with `source buildtools/environment-setup-x86_64-pokysdk-linux` and
>   `source setupsdk` (steps 2 and 3).

| Item | Source |
|------|--------|
| AMD / Yocto layers (poky, meta-xilinx, meta-xilinx-tools, meta-petalinux, meta-openembedded, meta-vitis, ...) | `repo` manifest <https://github.com/Xilinx/yocto-manifests>, branch `rel-v2024.1` → `sources/` (not tracked) |
| Product layer `meta-p01` and the Enclustra layers | [../layers](../layers/), shared with the PetaLinux project |
| Hardware description | `../VIVADO_2024.1/export/p01_xu1_st1.xsa` (written by the hardware build, not in the repository) |
| `meta-p01-yocto` (this folder) | Yocto-only settings that PetaLinux generates from `project-spec/configs` |

## meta-p01-yocto

| File | PetaLinux equivalent |
|------|----------------------|
| `conf/machine/p01-xu1-st1-xczu6eg.conf` | `build/conf/machine/refdes-xu1-st1-xczu6eg.conf` generated by `petalinux-config` (gen-machineconf): requires the Enclustra `refdes-xu1-st1` machine, override `enclustra-sd`, XSA path. The name must contain `eg`: the Enclustra layer derives `SOC_VARIANT` from the machine name (EG → `mali400` in `MACHINE_FEATURES`). |
| `recipes-bsp/device-tree/files/system-conf.dtsi` | `components/plnx_workspace/device-tree/device-tree/system-conf.dtsi`, generated from `configs/config`; included by the Enclustra `system-user.dtsi` |
| `recipes-core/images/petalinux-image-minimal.bbappend` | `configs/rootfs_config` (`p01-app`, `packagegroup-petalinux-vitisai`, ...), users (`petalinux` + sudo, password at first login); image types as in PetaLinux without jffs2: no wic (Enclustra `enclustra-sd`) and no `wic.qemu-sd` (`zynqmp-generic`, QEMU) |
| `recipes-core/base-files/base-files_%.bbappend` | hostname `p01-xu1-st1` |
| `recipes-core/systemd/` | `configs/systemd-conf/wired.network` (static IP 192.168.2.10/24) |

Differences to the PetaLinux image: the PetaLinux U-Boot templates (`platform-top.h`, ubifs boot
patch in `project-spec/meta-user`) are not used, U-Boot is built as AMD / Enclustra ship it; the
kernel is deployed as `Image` (not `image.ub`), see step 6.

## Steps

Steps 1 and 2 are done once. Each step starts in the repository root (`cd` to it first if a
previous step left the terminal in `YOCTO_2024.1/` or `YOCTO_2024.1/build/`).

### 1. Host (Ubuntu 22.04)

Yocto host packages (most of them are also needed for PetaLinux), the UTF-8 locale and the Google
`repo` tool:

```bash
sudo apt-get install -y gawk wget git diffstat unzip texinfo gcc build-essential chrpath socat \
    cpio python3 python3-pip python3-pexpect xz-utils debianutils iputils-ping python3-git \
    python3-jinja2 libegl1-mesa libsdl1.2-dev python3-subunit mesa-common-dev zstd lz4 \
    liblz4-tool file locales libacl1
sudo locale-gen en_US.UTF-8
mkdir -p ~/.local/bin
curl -fsSL https://storage.googleapis.com/git-repo-downloads/repo -o ~/.local/bin/repo
chmod a+x ~/.local/bin/repo
repo version                  # ~/.local/bin must be in PATH (default on Ubuntu after a new login)
```

### 2. Yocto buildtools and AMD layers

```bash
cd YOCTO_2024.1

# Yocto buildtools 4.1.4 (own tar, python3, git) -> buildtools/ (not tracked)
U=https://downloads.yoctoproject.org/releases/yocto/yocto-4.1.4/buildtools
curl -fLO $U/x86_64-buildtools-nativesdk-standalone-4.1.4.sh
echo "8cdd884e7fcb4408d67d59a1944c8faaf1ef6ce668abe937fa900715f5d72f1c  x86_64-buildtools-nativesdk-standalone-4.1.4.sh" | sha256sum -c -
sh x86_64-buildtools-nativesdk-standalone-4.1.4.sh -y -d $PWD/buildtools
rm x86_64-buildtools-nativesdk-standalone-4.1.4.sh

# AMD layers -> sources/ (not tracked)
repo init -u https://github.com/Xilinx/yocto-manifests.git -b rel-v2024.1
repo sync -j8                 # 19 layers, about 1.5 min
```

Why buildtools: Ubuntu 22.04 `tar` from `1.34+dfsg-1ubuntu0.1.22.04.4` on (June 2026,
CVE-2025-45582 fix) opens directories with `openat2()`, which the langdale `pseudo` does not track:
with the host `tar`, `do_package` fails with `got *at() syscall for unknown directory` / `Cannot
open: Bad address`. PetaLinux is not affected because it uses its own tools. The buildtools of the
same Yocto release bring their own `tar`, `python3` and `git`.

### 3. Build directory, layers, local.conf

```bash
cd YOCTO_2024.1
source buildtools/environment-setup-x86_64-pokysdk-linux
source setupsdk               # creates build/ (templates from meta-petalinux) and enters it
bitbake-layers add-layer ../sources/meta-vitis
bitbake-layers add-layer ../../layers/meta-enclustra-amd/meta-enclustra-module \
                         ../../layers/meta-enclustra-amd/meta-enclustra-baseboard \
                         ../../layers/meta-enclustra-amd/meta-enclustra-refdes \
                         ../../layers/meta-p01
bitbake-layers add-layer ../meta-p01-yocto
```

Append the P01 settings to `build/conf/local.conf` (still in `build/`):

```bash
cat >> conf/local.conf <<'EOF'

# ---- P01 -----------------------------------------------------------------------------------
MACHINE = "p01-xu1-st1-xczu6eg"
INIT_MANAGER = "systemd"
# XSCT (device tree, FSBL, PMU firmware from the XSA) from the local Vitis installation.
# CHANGE THIS PATH: it is the Vitis 2024.1 installation of this build host
# (<xilinx-install>/Vitis/2024.1, the folder that contains bin/xsct).
USE_XSCT_TARBALL = "0"
XILINX_SDK_TOOLCHAIN = "/tools/Xilinx/Vitis/2024.1"
# Reuse the PetaLinux downloads and build results, then the AMD sstate server
DL_DIR = "${TOPDIR}/../../PETALINUX_2024.1/p01-xu1-st1/build/downloads"
SSTATE_MIRRORS = " \
    file://.* file://${TOPDIR}/../../PETALINUX_2024.1/p01-xu1-st1/build/sstate-cache/PATH \
    file://.* http://petalinux.xilinx.com/sswreleases/rel-v2024/aarch64/sstate-cache/PATH;downloadfilename=PATH \
"
INHERIT += "rm_work"
EOF
```

Then edit `XILINX_SDK_TOOLCHAIN` in `conf/local.conf` if Vitis is installed elsewhere, and check
that the configuration is read as intended (parses all layers, no build):

```bash
bitbake-layers show-layers
bitbake -e | grep -E '^(MACHINE|SOC_VARIANT|MACHINE_FEATURES|DISTRO|INIT_MANAGER|HDF_PATH|MACHINEOVERRIDES)='
```

Expected: `SOC_VARIANT="eg"` and `mali400` in `MACHINE_FEATURES` (from the `eg` in the machine
name), `enclustra-sd` in `MACHINEOVERRIDES`, `HDF_PATH` = the XSA, `DISTRO="petalinux"`,
`INIT_MANAGER="systemd"`.

- `INIT_MANAGER`: the petalinux distro leaves it unset; PetaLinux sets systemd in its generated
  configuration.
- XSCT (device tree, FSBL, PMU firmware from the XSA) is taken from the local Vitis installation
  instead of the XSCT tarball download.
- `DL_DIR` and the first `SSTATE_MIRRORS` entry reuse the PetaLinux project's downloads and build
  results; the second entry is the AMD sstate server PetaLinux also uses.
- `rm_work` removes each recipe's work directory after it is built (disk space, not build time).

### 4. First build: device tree

In the terminal of step 3 (already in `build/`) only `bitbake device-tree` is needed. In a new
terminal, the two `source` lines set up the environment again and enter `build/` (the existing
configuration is kept):

```bash
cd YOCTO_2024.1
source buildtools/environment-setup-x86_64-pokysdk-linux
source setupsdk
bitbake device-tree
dtc -I dtb -O dts -q tmp/deploy/images/p01-xu1-st1-xczu6eg/system.dtb \
  | grep -E 'bootargs|vid-formats|p01-preproc|dpuczdx8g|status = "disabled"'
```

The device tree is generated from the XSA by XSCT (meta-xilinx-tools), then the Enclustra board
files, `system-conf.dtsi` (meta-p01-yocto) and `p01-video.dtsi` / `p01-bootargs.dtsi` (meta-p01) are
added, as in the PetaLinux build. Expected: the `bootargs` with `root=/dev/mmcblk1p2 ... cma=700M`,
`xlnx,vid-formats = "yuyv"` and `"bgr888"`, `xlnx,p01-preproc-2.1`, `xlnx,dpuczdx8g-4.1`, and the
video pipeline nodes `disabled`.

### 5. Image

In `build/`, with the environment of step 4:

```bash
bitbake petalinux-image-minimal
ls -l tmp/deploy/images/p01-xu1-st1-xczu6eg/
```

`BOOT.BIN` (`xilinx-bootbin`: FSBL, PMU firmware, bitstream from the XSA, TF-A, DTB, U-Boot) is
built with the image (`EXTRA_IMAGEDEPENDS` of the zynqmp machines).

Messages like `Setscene task ... failed` / `Fetcher failure ... sstate` mean that a prebuilt result
was not found in a mirror and the task is built locally; the build is fine if the summary ends with
`all succeeded`.

### 6. SD card

`boot.scr` loads `image.ub` if present, otherwise `Image` and `system.dtb` from the boot partition.
Yocto deploys the kernel as `Image` (and `fitImage`, not named `image.ub`), so the boot partition
gets `Image` + `system.dtb`; an `image.ub` left on the card (e.g. from a PetaLinux image) must be
removed. `/dev/sdX` is the SD card on the host (check with `lsblk`, all data on it is erased):

```bash
D=YOCTO_2024.1/build/tmp/deploy/images/p01-xu1-st1-xczu6eg
SD=/dev/sdX
sudo umount ${SD}1 ${SD}2 2>/dev/null
sudo parted -s $SD mklabel msdos mkpart primary fat32 4MiB 260MiB mkpart primary ext4 260MiB 100% set 1 boot on
sudo mkfs.vfat -F 32 -n BOOT ${SD}1
sudo dd if=$D/petalinux-image-minimal-p01-xu1-st1-xczu6eg.ext4 of=${SD}2 bs=4M conv=fsync status=progress
sudo e2fsck -f ${SD}2 && sudo resize2fs ${SD}2
sudo mount ${SD}1 /mnt
sudo cp $D/boot.bin /mnt/BOOT.BIN
sudo cp $D/boot.scr $D/Image $D/system.dtb /mnt/
sudo umount /mnt
```

### 7. First boot

As with the PetaLinux image ([../PETALINUX_2024.1/README.md](../PETALINUX_2024.1/README.md#first-boot)):
serial console 115200 8N1, log in as `petalinux` (the password is set at the first login, `root` is
locked), static IP `192.168.2.10/24`, then `sudo p01-run.sh --pl-test` and `sudo p01-run.sh`.

## Result (2026-10-26)

Checked against the PetaLinux image and on the board:

| Item | Yocto (`tmp/deploy/images/p01-xu1-st1-xczu6eg/`) |
|------|-----------------------------------------------|
| `boot.bin` | `fsbl.elf`, `pmufw.elf`, `download-p01-xu1-st1-xczu6eg.bit` (bitstream), `arm-trusted-firmware.elf`, `system-top.dtb`, `u-boot.elf` |

| Board | boots from SD, `--pl-test` and the camera pipeline run as with the PetaLinux image |

## Known issues and their fixes (already applied above)

| Symptom | Cause | Fix |
|---------|-------|-----|
| `do_package`: `got *at() syscall for unknown directory`, `Cannot open: Bad address` | Ubuntu `tar` with `openat2()` (June 2026 security update) under the langdale `pseudo` | Yocto buildtools 4.1.4 (step 2) |
| `Nothing RPROVIDES 'libmali-xlnx'` (`missing required machine feature 'mali400'`) | Machine name without `eg`: the Enclustra layer selects the SoC variant from `MACHINE` (no match → DR) | Machine `p01-xu1-st1-xczu6eg` |
| `do_image_wic`: `Actual rootfs size ... is larger than allowed size 409600 kB` | `wic.qemu-sd` from `zynqmp-generic` uses the Enclustra `mmc-image.wks` (400 MB rootfs partition) | `wic.qemu-sd` removed in `meta-p01-yocto` (no wic images at all) |
